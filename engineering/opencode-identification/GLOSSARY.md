# Идентификация сессий и процессов OpenCode — Глоссарий

Термины, которые появляются в уроках этого курса. Определения сжатые: что термин
**есть**, а не как его применять.

## Идентификаторы

**Session ID**:
Уникальный идентификатор диалога, формат `ses_` плюс 26 base32-подобных символов.
Хранится в БД, переживает перезапуск сервиса. Единственный устойчивый идентификатор
в opencode.
_Avoid_: conversation id, chat id, run id

**Instance UUID**:
Идентификатор запущенного экземпляра фонового сервиса, лежит в
`service.json`. Генерируется заново при каждом старте.
_Incident_: воспринимается как постоянный ID установки, но меняется
_Equivalent_: install id, server id

**Run**:
Восьмисимвольный идентификатор процесса opencode, стоит в каждой строке лога как
`run=<8 hex>`. Единственное поле, различающее процессы, но не переживает рестарт и
не выдаётся ни env, ни API.
_Equivalent_: process run, trace id

**PID**:
Идентификатор процесса ОС. Значение из `/api/info` принадлежит фоновому сервису и
общо для всех агентов на машине.
_Incident_: принимается за идентификатор процесса агента

**Service PID**:
PID фонового сервиса, возвращаемый `/api/info`. Один на пользователя, не
различает агентов между собой.

## Свойства

**Many-to-many (run↔session)**:
Один `run` встречается в логе с несколькими сессиями, и одна сессия — с
несколькими `run`. Поэтому «run одной сессии» может быть неоднозначным.
_Avoid_: «run принадлежит сессии»

**Trainee change (agent)**:
Агента сессии можно переключить на ходу через `POST /api/session/{id}/agent`.
Значение свободной формы: в БД встречаются `Sisyphus - ultraworker` и
`Atlas - Plan Executor`.
_Avoid_: стабильный агент сессии

**Parent session**:
Сессия, породившая дочернюю, через `parent_id`. 54% сессий в БД дочерние
(215 из 396), у корневых `parent_id` пуст.
_Equivalent_: child session, subagent session

**Project ID**:
Идентификатор проекта, 40 hex. Не равен sha1 пути: воркtree порождают несколько
проектов на один и тот же каталог, плюс есть проект `global` для `/`.
_Avoid_: путь проекта, project path

## Атрибуция в репозитории

**Assisted-by**:
Трейлер в коммите вида `Assisted-by: <позывной> (<модель>, issue #<N>)`,
последним абзацем сообщения. Обязателен для коммитов с кодом по схеме проекта.
_Avoid_: author, committer

**Callsign**:
Позывной агента из `docs/agents/roster.md`, соответствует email
`<callsign>@agents.local`. Определяет author коммита.
_Incident_: используется как идентификатор модели

**Author**:
Имя и email, с которыми git записал коммит. У агента — позывной из ростера, а не
аккаунт GitHub.

**Attribution cutover**:
Дата 2026-02-01, с которой атрибуция по позывным применяется. Коммиты раньше
остаются неатрибутированными и по позывному не отделяются.

## Инфраструктура

**Service registration**:
Файл `~/.local/state/opencode/service.json`, куда сервер пишет UUID, версию, URL,
PID и пароль при старте. Перезаписывается на каждом старте.

**Service config**:
Файл `~/.config/opencode/service.json`, отдельно от регистрации. Содержит пароль.
При переносе конфигурации нужны оба файла.

**Auth (Basic)**:
Аутентификация HTTP API — HTTP Basic с логином `opencode` и паролем из
`service.json`. Не Bearer: Bearer даёт 401.

**XDG isolation**:
Создание второго инстанса через подмену `XDG_STATE_HOME`, `XDG_DATA_HOME`,
`XDG_CONFIG_HOME`, `XDG_CACHE_HOME`. Позволяет проверять поведение сервиса,
не трогая основной.

**Client-server architecture**:
Устройство opencode: интерфейсы подключаются к фоновому сервису, который владеет
сессиями, плагинами, разрешениями и выполнением инструментов.
