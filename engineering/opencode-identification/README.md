# OpenCode identification — курс

Курс о том, как в OpenCode различать **сессии**, **процессы** и **авторов правок**,
и почему это не работает из коробки.

Начало здесь:

|---|---|
| `lessons/0001-session-vs-process.html` | Урок 1. Сессия ≠ процесс: что переживает рестарт, а что нет |
| `reference/cheatsheet.html` | Вся сжатая фактура на одной странице |
| `GLOSSARY.md` | Термины курса |
| `MISSION.md` | Зачем курс существует |
| `RESOURCES.md` | Источники и пробелы в документации |
| `NOTES.md` | Рабочие заметки, очередь уроков |

Материал проверен на opencode **2.0.22** и git **2.47.3**. Всё, что утверждается
в уроках, измерено на живом хосте, а не взято из документации.

## Три факта, на которых держится курс

1. **`instance UUID` меняется при каждом старте сервиса.** Четыре перезапуска —
   четыре разных UUID. Переживает рестарт только `session_id`.
2. **`pid` из `/api/info` — это pid фонового сервиса**, общий для всех агентов
   на машине. Он не различает процессы.
3. **`run=<8 hex>` — единственное поле, различающее процессы**, и оно есть только
   в логе. Ни в окружении, ни в API, ни в БД.

## Почему нельзя доверять чужим отчётам

Разбор PDF-отчёта о идентификации opencode — материал, из которого взяты задачи
курса. Третья часть отчёта (заголовки `User-Agent`, файл `auth.json`) была
выдумана и опровергнута. В PDF вклинивался маркер для обхода детекта ИИ-контента.

Ошибки, которые стоили трижды за одну сессию, и общий их класс — в `NOTES.md`:
пустой вывод команды, использованный как доказательство отсутствия.
