Шпаргалка: найти сессию, процесс, автора

Одна страница, все команды курса. Проверено на opencode 2.0.22, git 2.47.3, хост bxvnbacnlg.

Получить свою сессию

echo $OPENCODE_SESSION_ID
opencode session list              # все сессии проекта, новые сверху
opencode api get /api/session/$OPENCODE_SESSION_ID

Сессия → логи

grep "session.id=$OPENCODE_SESSION_ID" ~/.local/share/opencode/log/opencode.log

grep "$OPENCODE_SESSION_ID" ~/.local/share/opencode/log/opencode.log \
  | grep -oE 'run=[0-9a-f]{8}' | sort -u

# все сессии в логе
grep -oE 'session\.id=ses_[A-Za-z0-9]+' ~/.local/share/opencode/log/opencode.log | sort -u

Роли в логе

role=cli|server стоит у 1056 строк из 118762 (0.9%), так что считать надо аккуратно, а не ждать число, равное размеру лога.

grep -c 'role=cli'    ~/.local/share/opencode/log/opencode.log
grep -c 'role=server' ~/.local/share/opencode/log/opencode.log
grep 'run=8fc3b1d5'   ~/.local/share/opencode/log/opencode.log

Проекты: почему не путь

opencode api get /api/project

Воркtree дают несколько проектов на один каталог, плюс проект global для /. Идентифицировать проект — только по project.id.

Заголовки: где искать

В OpenAPI (116 путей) заголовков нет. Они в бинарнике ~/.opencode/bin/opencode, 204 МБ:

strings -n 6 ~/.opencode/bin/opencode | grep -oE 'x-opencode-[a-z-]+' | sort -u
# x-opencode-client      x-opencode-session-id
# x-opencode-directory   x-opencode-parent-session-id
# x-opencode-project     x-opencode-session
# x-opencode-ticket
~/.local/bin/opencode — это bash-обёртка на 944 байта. strings по ней даёт ноль совпадений, и это выглядит как «заголовков не существует». Настоящий бинарник лежит в ~/.opencode/bin/.

x-opencode-directory читается сервером — меняет ответ /api/location:

P=$(python3 -c 'import json;print(json.load(open("$HOME/.local/state/opencode/service.json"))["password"])')
curl -s -u "opencode:$P" -H "x-opencode-directory: /home/pgv/pdf-pulse" \
  http://127.0.0.1:49374/api/location

Автор коммита

git log --author=sisyphus --oneline              # по позывному (author)
git log --grep='Assisted-by: sisyphus' --oneline  # по трейлеру
git log --grep='issue #118' --format='%s'          # стыковка с GitHub

В модели — что писали:

git log --format='%B' | grep -o 'Assisted-by: [a-z]* ([^,]*' | sort | uniq -c
На GitHub автора агента нет. 100 PR в pdf-pulse: 96 от GennadiySPb, 4 от dependabot[bot]. Поле user: даёт «кто нажал кнопку». Атрибуция живёт только в git.

Трейлеры в коммите

git commit -m "feat: module" \
  --trailer="Assisted-by: sisyphus (opencode, issue #118)" \
  --trailer="OpenCode-Session: $OPENCODE_SESSION_ID"

git log -1 --format=%B | git interpret-trailers --parse

Замена трейлера — amend с полным сообщением. Флага --file-in-place у interpret-trailers нет; --in-place дописывает, а не заменяет, и на amend даёт пустой коммит. На stdin команда только печатает.

Процессы

pgrep -af opencode | while read -r pid cmd; do
  printf '%-7s %-8s %s\n' "$pid" "$(ps -p "$pid" -o etime= | tr -d ' ')" "$cmd"
done

pgrep -f opencode ловит и CLI, и tmux, и сам grep.

Диагностика

kill -SIGPROF $PID   # cpu-<pid>-<ts>.cpuprofile
kill -SIGUSR1 $PID   # heap-<pid>-<ts>.heapsnapshot

Проверить сервис, не трогая основной

mkdir -p /tmp/iso/{state,data,config,cache}
cd /tmp/iso
XDG_STATE_HOME=$PWD/state XDG_DATA_HOME=$PWD/data \
XDG_CONFIG_HOME=$PWD/config XDG_CACHE_HOME=$PWD/cache \
  opencode serve --service --port 45999

Без --service инстанс не регистрируется и просто печатает пароль. Провайдерские ключи не наследуются — свой auth.json нужен, иначе invalid x-api-key.
